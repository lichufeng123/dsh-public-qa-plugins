# 固定测试报告格式与证据包规范

本规范用于功能测试、回归测试、缺陷验收、快速测试和一站式测试的正式或临时报告。它融合两种阅读路径：先按“测试原理/测试点”理解为什么这样测，再按“稳定用例/业务对象”查看每个对象的执行结论和完整证据。

## 固定章节

报告章节顺序固定如下；无内容时写“无”及原因，不静默删除章节：

1. 结论先行
2. 测试目标、测试原理与测试点
3. 范围、版本、角色、Fixture与Oracle
4. 测试执行总览
5. 核心业务流程与逐测试点结果
6. 按稳定用例/业务对象的证据包
7. 缺陷、候选问题与问题定性
8. 未执行项、阻塞项与发布风险
9. 需求/规则/用例/证据追溯
10. 产品确认暂不处理与待确认口径
11. 执行资产、待优化项与复测建议
12. 结论权限、隐私与报告修订记录

`templates/standard-test-report.example.md` 是固定人类可读模板；`schemas/test-report-package.schema.json` 是结构化报告包合同；`templates/test-report-package.example.json` 是脱敏示例。

## 第一索引：测试原理与测试点

每个测试点使用稳定 `TP-*` ID，至少回答：

- 测什么：业务行为、状态、角色或数据关系。
- 为什么测：要区分的风险假设，不能只写页面操作。
- 怎么激励：输入、动作或状态变化。
- 怎么判：原子断言及独立Oracle。
- 用什么数据：Fixture、角色、组织、环境和版本。
- 留什么证据：截图、录屏、接口、日志、固定ID回读或数据快照。
- 结论边界：这个测试点能证明什么，不能证明什么。

测试点总览优先放在报告前部。读者不应翻到逐条结果后才知道测试设计原理。

## 第二索引：稳定用例或业务对象证据包

一次自动化的业务对象是会员、订单、员工、接待、门店、文件或缺陷时，每个对象建立一个独立证据包。默认一对象一稳定用例；若一个用例包含多个对象，必须解释关系并分别绑定稳定身份。

每个证据包固定包含：

1. 用例ID、标题、业务对象稳定ID、角色、组织和Fixture。
2. 输入及动作链，禁止按“最新记录”定位。
3. 原子断言逐项状态：通过、失败、阻塞或未执行。
4. 实际结果与结论边界。
5. 分层证据及原图引用。
6. 如有拼图：拼图ID、回执、格子索引及原图保留声明。

层数不是固定三层；但同一功能重复执行时层级名称和顺序必须稳定。例如智能耳机五维记忆可以固定为：

```text
接待事实/分析结果 → 用户记忆生成终态 → 五维写入与逐维证据
```

十个会员就是十个稳定用例/证据包，每个包都必须能独立回答该会员的输入、接待身份、事实、生成状态、五维结果和结论。不得用总计“10/10成功”替代逐对象证据。

## 证据拼图使用规则

当同一证据层有2～6张并列截图，共同证明一个原子结论且缩放后仍可读时，使用 `report-evidence-montage`：

- 原图继续保持权威，拼图只是报告阅读视图。
- 拼图前拦截缺图、白图、重复图、错身份、尺寸不足和未完成隐私复核的图。
- 7～12张按子结论拆成多张拼图；超过12张使用分组索引，不做缩略图墙。
- 操作时序、加载过程和动态状态优先使用录屏。
- 发布后回读图片块、标题唯一性、位置和revision。

## 执行状态与统计

固定状态：`通过`、`不通过`、`阻塞`、`未执行`、`设计如此`、`待优化`、`忽略`。

- 通过率只按 `通过 / 已执行` 计算；已执行包括通过、不通过、设计如此、待优化。
- 阻塞、未执行和忽略单列；忽略不进入适用用例数和通过率分母。
- 派生检查数、截图数、日志数、模型任务数不能冒充正式用例数。
- 总体流程通过与内容正确必须分别统计。

## 缺陷与候选问题

每个问题必须区分：

- 已确认产品缺陷；
- 高置信候选问题；
- 环境/角色/数据/异步/缓存/版本/脚本问题；
- 待产品确认口径；
- 测试方法风险或假阳性排除。

实际、预期、独立Oracle、影响、证据、复现范围和当前处置分别记录。页面差异或脚本失败不能自动升级为产品缺陷。

## 结论权限

报告必须明确：

- 正式验收/发布门禁，还是临时/AI初判；
- 哪些断言有直接证据；
- 哪些内容缺人工听辨、正式规则或独立Oracle；
- 报告是否授权发布通过；
- 历史结果是否仅作背景，不能计入本轮通过。

## 发布与回读

- 飞书首次创建后回读正文；更新已有文档时绑定写前revision。
- 媒体上传后核对图片/视频块数量、标题唯一性、章节位置和revision。
- 图片修复使用块ID定点替换，不在文末追加同标题重复图。
- 保存本地报告SHA、证据清单SHA、飞书revision和发布回执。
- 账号、密码、Cookie、Token、完整手机号、客户隐私和未脱敏载荷不得进入报告。
